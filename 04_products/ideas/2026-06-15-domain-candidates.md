## 上位 3 候補（D-002 通り）

スコア平均で上位 3 を抽出：

### 🥇 候補 1: 同人/インディー楽曲メタデータ整理 SaaS（平均 7.9）

- **対象**: 自主リリースのインディー音楽家・ボカロ P・トラックメイカー
- **困りごと**: 各配信ストア（Spotify / Apple Music / TuneCore / DistroKid）に出すたびに ISRC / ジャンルタグ / クレジットを手入力。1 曲 30-60 分溶ける
- **解決**: 楽曲ファイル + 簡易テキスト投入 → AI がメタデータ生成 → 各ストア向け CSV / API ペイロードに整形
- **収益モデル**: SaaS 月額（推定 （非公開）-3,000/月）
- **強み**: CTO/COO 両方推し / JASRAC 温存可能 / 運用負荷最低
- **弱み**: リテンションは「リリース頻度が落ちる顧客」で漏れる

### 🥈 候補 2: 同人音楽 リリース一式代行（平均 7.8）

- **対象**: ボカロ P・同人音楽サークル主宰（M3 / 例大祭出展層）
- **困りごと**: 曲は作れるが、ジャケ案出し / クロスフェードデモ / 配信ストア入稿 / 告知文 / X 投稿スケジュールが全部辛い
- **解決**: AI で「告知文 + ジャケラフ 3 種 + クロスフェード台本 + メタデータ + 投稿スケジュール」を 1 案件 （非公開）-15,000 で受注
- **収益モデル**: 受注型（（非公開）/件）
- **強み**: 早期キャッシュ化最強（3 件/月で黒字化、3-4 ヶ月達成）・粗利 85%
- **弱み**: スケーラビリティが SaaS より劣る

### 🥉 候補 3: 個人ゲーム開発者 Steam ストアページ最適化（平均 7.5）

- **対象**: Steam / itch.io にリリースする個人ゲーム開発者
- **困りごと**: ストアページ説明文 / タグ / スクショ配置 / 多言語対応でウィッシュリスト数が伸びない
- **解決**: ゲーム概要 + スクショ投入 → AI が「説明文（5 言語）+ タグ推奨 + スクショ配置案 + トレーラー台本」生成
- **収益モデル**: 受注型（（非公開）/件・粗利 90%）
- **強み**: 3 役員全員が起案（合議性最高）・**単位経済性 8.8 で全候補最強**・1 件/月で黒字化（2-4 ヶ月達成）
- **弱み**: 顧客プール（日本語圏インディー開発者）が薄く、月次 1 件継続が論点

## スパイク 2 件ペアの推奨

D-002 で「上位 3 のうち 2 件をスパイク」と定めた。シャチョーの推奨ペア 3 案：

### 推奨ペア A（**第一推奨**）: 候補 1 + 候補 3

**音楽メタデータ SaaS（ストック型）+ ゲーム Steam ストア最適化（受注型・高単価）**

- ドメイン分散（音楽 vs ゲーム）→ 1 つ失敗しても他方が残る
- 収益モデル分散（SaaS vs 受注）→ 早期キャッシュ化と中長期スケールの両建て
- どちらも JASRAC 温存可能
- 全候補中、3 役員合議性が最も高い 2 件

### 推奨ペア B: 候補 1 + 候補 2

**音楽メタデータ SaaS + 音楽リリース一式代行（両方音楽）**

- JASRAC 導線を集中活用可能
- 失敗時に統合可能（メタデータ機能をリリース一式に組み込む等）
- 弱点: ドメイン集中リスク

### 推奨ペア C: 候補 2 + 候補 3

**音楽リリース一式代行 + ゲーム Steam ストア最適化（両方受注型）**

- 早期キャッシュ化を最優先
- 弱点: ストック型を試せず、スケール検証が遅れる

## 取締役会判断要請事項

### 1. スパイクペアの決定

ペア A / B / C のいずれを選ぶか。

### 2. 候補 14 の F5 法務リスク判定（COO 確認事項 1）

「権利・契約一次相談 AI」は、AI による法的助言が弁護士法 72 条のグレーゾーンに踏み込む可能性あり。

- (a) スパイク対象から除外（推奨）
- (b) 法務調査後に再判定
- (c) 候補 14 を別枠でスパイクする
