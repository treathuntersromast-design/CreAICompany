# 決議ログ

取締役会で決定された事項を時系列で記録する。各決議は `D-NNN` で採番する。

## 書式

```
## D-NNN: <タイトル>
- **日付**: YYYY-MM-DD
- **議題**: 何を決めようとしたか
- **決定**: 決定内容（具体的に）
- **担当**: 誰が実行するか
- **期限**: いつまでに
- **関連議事録**: minutes/YYYY-MM-DD.md
- **関連 daily-log**: 06_operations/daily-log/YYYY/MM/YYYY-MM-DD.md
```

## D-002: 事業ドメイン探索方針

- **日付**: 2026-06-15
- **議題**: どの事業ドメインに入るかを決めるための「絞り込み方針」を確定する
- **決定**: 4 段ファネル（フィルタ → スコアリング → スパイク → 確定）で進める。
  1. **フィルタ F1〜F5**:
     - F1: AI ネイティブ性（AI が価値の 70% 以上を直接生み出せる）
     - F2: フィードバック周期 < 2 週間
     - F3: 失敗の影響半径が局所的
     - F4: 初期顧客 5 名に到達可能（クリエイター領域はオーナー人脈、それ以外はクラウドワークス / ランサーズ経由）
     - F5: 法務 / コンプラ未確定領域でない
  2. **スコアリング**（100 点満点・中立）: 学習価値 30 / 単位経済性 25 / 立ち上げ速度 20 / オーナー関心度 15 / 差別化 10
  3. **候補生成プールの偏向**: クリエイター業界関連を **70% 以上** に寄せる（音楽 / 映像 / 文字 / 絵 / ゲーム / 配信。舞台は除外）
  4. **ネットワーク資産**: 音楽領域については JASRAC 理事経由の導線が利用可（出し惜しむべきリソース。スパイク段階で MVP の感触が良かった場合のみ使用）
  5. **候補生成体制**: `@cto` `@cfo` `@coo` の subagent を活用して各役員が 5〜7 候補ずつ起案、シャチョーが統合して 10〜15 に整える
  6. **タイムボックス**: W1（〜2026-06-22）候補生成 / W2（〜2026-06-29）スコアリングと上位 3 確認 / W3〜W4（〜2026-07-13）スパイク 2 件並走 / W4 末 ドメイン確定決議
- **担当**: シャチョー（プロセス推進）、`@cto/@cfo/@coo`（候補起案）
- **期限**: ドメイン確定決議 = 2026-07-13

## D-007: 「舞台」除外の境界定義（CTO B1 解消）

- **日付**: 2026-06-15
- **議題**: [D-002](#d-002-事業ドメイン探索方針) で除外した「舞台」の境界を定義する
- **決定**: 「**物理空間（リアル会場）での実演がコンテンツの中核となる活動**」を「舞台」として除外する。デジタル空間での "ライブ" 的活動は対象に含む。
  - 除外（× 舞台）: 小劇場演劇 / ミュージカル / 朗読会 / リアル会場ライブ（VTuber リアルライブ含む） / 同人音楽リアルイベント
  - 対象（◯）: VTuber 通常配信 / 配信内ライブ（バーチャル空間） / VR ライブ / ボイスドラマ・シチュ CD / 配信内 TRPG / 朗読配信 / ゲーム実況
  - グレー解消: 演劇脚本のテキスト的支援は ◯（脚本＝文字制作）、楽曲のライブ用アレンジ支援は ◯（楽曲制作）
  - 設計思想: AI で代替しにくい / 物理拘束強い / オーナー人脈薄い、の 3 条件を満たす領域を除外
- **担当**: CTO（B1 宿題はこれにて解消）
- **期限**: 即時発効
