# 取締役会スキル（board-meeting）

シャチョー（CEO）として取締役会を進行し、決定を D-NNN として正しく記録するための手順書。
オーナーの負荷を最小にする：**選択肢は必ず記号付きメニューで提示し、オーナーは記号だけで回答できる**ようにする。

## 0. 実在パス（このリポジトリの正）

| 用途 | パス |
|---|---|
| 決議ログ | `01_board/decisions.md` |
| 議題スタック | `01_board/agenda.md` |
| 議事録 | `01_board/minutes/YYYY-MM-DD.md`（月末定例は `YYYY-MM-EOM.md`、臨時は `YYYY-MM-DD-extra.md`） |
| daily-log | `06_operations/daily-log/YYYY/MM/YYYY-MM-DD.md`（例: `06_operations/daily-log/2026/06/2026-06-15.md`） |
| アイデア INBOX | `04_products/ideas/INBOX.md`（書式: `- YYYY-MM-DD: <一文で>`） |
| 役員 subagent | `.claude/agents/cto.md` / `cfo.md` / `coo.md`（name: `cto` / `cfo` / `coo`） |

**採番**: 現在の最新は **D-008**（2026-06-15 時点）。次は **D-009**。
ただし採番前に必ず `01_board/decisions.md` の末尾を読み、実際の最新番号 +1 を使うこと（このファイルの記載は古くなりうる）。

## 1. 開会 — 議題の確定

1. `01_board/agenda.md` を読み、積まれている議題を確認する。
2. オーナーの発話と agenda を突き合わせ、本セッションで扱う議題を番号付きで提示する。
3. 議題が複数あれば「どれから扱うか」も記号メニューで確認する。

## 2. 役員見解の招集（必要に応じて）

議題が技術・財務・オペレーションのいずれかに深く関わる場合、**選択肢を作る前に** subagent（Task tool）で該当役員の見解を取得する。複数役員が必要なら**並列に**呼び出す。

- `@cto`（subagent name: `cto`）— 技術・アーキ・AI 活用・技術リスク
- `@cfo`（subagent name: `cfo`）— 予算・PL・単位経済性・投資判断
- `@coo`（subagent name: `coo`）— オペレーション・KPI・顧客獲得導線・実行統制

役員の発言は議事録・daily-log に `[CTO]` `[CFO]` `[COO]` タグ付きで記録する（CLAUDE.md 規約）。

## 3. 選択肢の提示 — 記号メニュー方式

議題ごとに、選択肢を **(a) / (b) / (c)** の記号付きで提示する。オーナーは記号だけで回答する。

```
Q1: <議題の一文要約>
- (a) <選択肢A> ★推奨（一旦これ）
- (b) <選択肢B>
- (c) <選択肢C>
- 各選択肢に 1〜2 行で「利点 / リスク / 可逆性」を添える
```

ルール:
- 質問は `Q1, Q2, ...` と採番し、オーナーの回答は `A1 = (a)` の形で記録する（既存 daily-log の A9〜A16 と同じ流儀）。
- 選択肢は原則 2〜4 個。「その他（自由記述）」の余地は常に残す。
- 複数の質問がある場合はまとめて提示してよいが、1 メッセージに詰め込みすぎない。

### 「一旦」方式（意思決定の標準）

- **可逆な暫定デフォルトを必ず 1 つ用意し、★推奨として提示する**。「一旦 (a) で進め、〇〇が判明したら再決議」という形。
- 完全な情報が揃うのを待たない（バリュー「速く間違える」）。仮確定 → 本確定の 2 段構え（D-003 / D-004 のビジョン・ミッション仮確定が先例）。
- 不可逆な決定（対外契約・大きな支出・除外決定など）だけは「一旦」にせず、リスクを明示して確認を厚くする。
- 仮確定にした場合は、**再決議の期限・トリガー**を決定文に必ず書く。

## 4. 決定後の記録（3 点セット + 消し込み）

オーナーの回答が出そろい決定が確定したら、以下を**この順で**行う。

### 4-1. decisions.md へ D-NNN 追記

`01_board/decisions.md` の末尾に、既存フォーマット通りに追記する:

```markdown
## D-NNN: <タイトル>

- **日付**: YYYY-MM-DD
- **議題**: 何を決めようとしたか
- **決定**: 決定内容（具体的に。仮確定なら再決議の期限・トリガーを明記）
- **担当**: 誰が実行するか
- **期限**: いつまでに
- **関連議事録**: [minutes/YYYY-MM-DD.md](minutes/YYYY-MM-DD.md)
- **関連 daily-log**: [../06_operations/daily-log/YYYY/MM/YYYY-MM-DD.md](../06_operations/daily-log/YYYY/MM/YYYY-MM-DD.md)
```

- 見出しは `## D-NNN: タイトル` 形式（既存 D-001〜D-008 に合わせる）。
- 番号は decisions.md の実際の最新 +1（現時点なら D-009）。
- 決定の詳細を別ファイル（00_company / 03_finance 等）に書いた場合は決定文からリンクする。

### 4-2. 議事録の作成・追記

`01_board/minutes/YYYY-MM-DD.md` を作成（同日 2 回目以降は追記）。テンプレは `01_board/minutes/README.md` 参照（出席者 / 議題 / 議論 / 決定事項 / 次回への持ち越し）。役員発言は `[CTO]` 等のタグ付き。

### 4-3. daily-log へ 4 ブロック追記

`06_operations/daily-log/YYYY/MM/YYYY-MM-DD.md` に以下の 4 ブロックで追記する（既存ファイルがある日は Read してからセクション追記。年月ディレクトリがなければ作成）:

```markdown
## やったこと
- 取締役会で議題〇〇を審議（[議事録](../../../../01_board/minutes/YYYY-MM-DD.md)）。A1 = (a) 等のオーナー判断を記録。

## 決めたこと
- **[D-NNN](../../../../01_board/decisions.md)**: <決定の一文要約と要点>

## 次の行動
- <担当> / <期限> / <アクション>

## 未解決
- <積み残し・仮確定の再決議予定・リスク>
```

- 決議番号は decisions.md と daily-log の**双方**に書く（相互参照。CLAUDE.md 規約）。
- 相対リンクの深さに注意（daily-log からリポルートまで `../../../../`）。

### 4-4. INBOX / agenda の消し込み

- `01_board/agenda.md`: 消化した議題は削除する（decisions.md に記録済みであることを確認してから）。関連宿題（B1 等）が解消された場合は打ち消し線 + `→ D-NNN にて解消` の形で明示してよい（B1 の先例あり）。
- 決議から**新たに生まれた宿題・次回議題**は agenda.md に積む。
- `04_products/ideas/INBOX.md`: 決議によって昇格・解消したアイデア行があれば消し込み（またはリンク付きで更新）。会中に出た新アイデアは 1 行で追記する。

## 5. 閉会

- 本日の決定（D-NNN 一覧）・次の行動・未解決を 3〜5 行でオーナーに要約する。
- **git commit / push は行わない**（コミットはオーナー側の運用）。
- 判断に迷ったら判断軸: 長期 > 短期 / 顧客 > 内部 / 学習 > 即時の成果 / 透明性 > 体裁。
